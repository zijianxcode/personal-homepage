六、安全整改与发布基线阶段（2026-03-18 ~ 2026-03-19）
--------------------------------------------------------------------------------

背景：
- 本轮安全检查发现多个“功能可用但安全模型不成立”的问题：
  1. 管理后台入口 key、许可码、受限内容链接曾放在前端/仓库中
  2. 管理员鉴权缺少服务端会话与登录限流
  3. 访客私信读取依赖前端可伪造标识
  4. 公共页面曾存在第三方脚本执行入口

整改内容：
- 私信系统改为服务端签发短期会话 token
- 管理后台增加登录限流、失败延迟、`Authorization` 鉴权
- 受限 Things 内容改为服务端校验许可码后再返回内容
- 受限链接移出受版本控制的前端文件，改为服务端配置
- 新增 CloudBase 自建访客 UV 统计，先与原第三方计数并行运行
- `floating-clock` 页面改为本地 vendored 依赖，不再从外部 CDN 执行脚本
- 补充本地静态服务安全响应头
- 构建脚本扩展为完整复制整站静态资源，避免安全修复遗漏到发布产物

原因复盘：
- 之前更多从“页面是否能工作”出发，而不是从“权限边界是否真实成立”出发
- 对前端可见信息、第三方脚本、受限内容和发布基线缺少单独的安全审查环节
- 缺少“先对齐 GitHub main，再改动、再发布”的强制执行习惯

后续强制要求：
- 任何访问控制、受限内容、后台入口都必须服务端校验
- 仓库中禁止出现明文访问码、后台 key、真实受限链接
- 新增第三方脚本前必须先说明原因、风险和回滚方案
- 每次发布前必须执行安全检查清单，并将结果写入迭代记录

                              第三部分：技术实现总结
================================================================================

一、核心功能
--------------------------------------------------------------------------------
1. 单页应用架构
   - 三个 Tab（Work / Info / Things）无刷新切换
   - CSS 控制显示/隐藏 + opacity 过渡

2. 中英双语切换
   - data-lang 属性标记
   - CSS 伪类控制显隐（[data-lang="cn"] .lang-en { display: none }）
   - 不使用 JS 条件渲染

3. 粒子背景
   - Canvas 2D 绘制
   - script.js 中实现

4. 文字动效
   - TextScramble 乱码效果
   - 滚动触发（Intersection Observer）
   - 字符级扰动与自愈（.char-unit）

5. Visual Coding 子页面
   - 4 列 grid 布局（桌面）/ 2 列（移动端）
   - 卡片内嵌 iframe 实时预览
   - overlay 阻止 iframe 拦截鼠标事件

6. Three.js 实验作品
   - Floating Clock：3D 物理模拟、Fresnel 着色器、多主题
   - Kinetic Typography Clock：弹簧物理、多数字系统


二、技术栈
--------------------------------------------------------------------------------
- HTML5 + CSS3 + Vanilla JavaScript（无框架）
- Three.js r128（3D 场景）
- Canvas 2D（粒子系统）
- CSS Custom Properties（设计令牌）
- Intersection Observer API（滚动触发）
- CSS Grid + Flexbox（布局）
- Git LFS（大型文件）


三、部署方案

================================================================================
                              第四部分：踩坑记录与经验总结
================================================================================

一、CSS 布局坑
--------------------------------------------------------------------------------
坑 1：Info 页工作经历对齐问题
现象：日期列与"联系我"区块不对齐
原因：使用 flex 布局时，日期列宽度计算不一致
解决：改用 CSS Grid，固定列宽 `grid-template-columns: 1fr 80px 280px`
相关提交：33f2407, 90d753d

坑 2：移动端响应式断点
现象：某些页面在小屏幕上布局错乱
原因：只设置了 768px 断点，没考虑更小屏幕
解决：增加 480px 断点，覆盖手机场景
相关提交：5ea0e65


二、iframe 交互坑
--------------------------------------------------------------------------------
坑 3：Visual Coding 卡片中的 iframe 拦截点击
现象：鼠标 hover 到卡片上时，无法点击跳转链接
原因：iframe 捕获了鼠标事件
解决：添加透明 overlay 层（::after），z-index: 1，cursor: pointer
相关提交：5ea0e65

示例代码：
```css
.vc-card-media--live::after {
    content: '';
    position: absolute;
    inset: 0;
    z-index: 1;
    cursor: pointer;
}
```


三、Three.js 资源坑
--------------------------------------------------------------------------------
坑 4：Three.js CDN 版本兼容性
现象：FontLoader 和 TextGeometry 在某些 CDN 版本中加载失败
原因：Three.js 模块加载顺序和版本匹配问题
解决：使用兼容的 CDN 版本组合：
    - three.min.js r128
    - FontLoader 和 TextGeometry 同版本
相关提交：5ea0e65

坑 5：Three.js 内存泄漏
现象：页面切换后，3D 场景仍在后台运行，内存占用增加
原因：未显式 dispose geometry、material、texture
解决：在组件销毁时显式调用 dispose()（项目中新页面尚未遇到，但需注意）
coding-standards.md 已记录此规范


四、多语言坑
--------------------------------------------------------------------------------
坑 6：中英文内容长度差异
现象：中文布局下某些文本溢出或换行不美观
原因：中文比英文约长 30%
解决：设计时为最长字符串预留空间，使用相对单位而非固定像素
相关规范：design-system.md 已记录


五、部署坑
--------------------------------------------------------------------------------
坑 7：CloudBase 构建输出目录
现象：构建脚本输出到根目录而非 dist
原因：package.json build script 配置错误
解决：修改为 "build": "cp -r . dist/" 或类似命令
相关提交：1a6c0a6

坑 8：PDF 文件占用仓库空间
现象：多次提交大 PDF 导致仓库体积膨胀
原因：直接提交 PDF 文件到 Git
解决：配置 Git LFS（.gitattributes）管理大型 PDF
相关提交：ea997bd


六、动画性能坑
--------------------------------------------------------------------------------
坑 9：动画导致页面卡顿
现象：粒子背景和文字动画在低端设备上掉帧
原因：动画属性选择不当，触发布局重排
解决：
    - 只动画 transform 和 opacity（合成层属性）
    - 使用 will-change 谨慎
    - 尊重 prefers-reduced-motion
相关规范：coding-standards.md 已记录
